# memo 2026-04-30 — fig 2 (GRE, Au) パネルデータ再生成・引継ぎメモ

別マシン (より高スペック) で fig 2 の (GRE, Au) パネルのデータ再生成を継続するための引継ぎ資料。

## 1. 目的

`dda_results/paper/figures/fig2_lc_convergence_nonsphere.pdf` の (GRE, Au) パネルが現状 **gate-suppressed** (描画されず空白)。原因: `convergence_gre_Au.hdf5` の `solver_err` が relaxed-gate (`PHASE7_RESIDUAL_THRESHOLD = 10⁻³`) を通らない (finest 2 mesh で `3.9×10⁻²` / `5.5×10⁻²`)。

**方針**: block-Krylov の subspace 拡張効果を利用し、`run_lc_convergence.jl` を **L=32 で実行**して finest 残差を 10⁻³ 以下まで落とす。出力 HDF5 の column 0 (= ZYZ identity orientation) のみを抽出する仕組みは既存スクリプトに内在しているので、図に出る "single orientation" の意味は保たれる。

## 2. このマシン (32 GB RAM) で完了した作業

### 2.1 block-VIEM.jl 側 — スクリプト改造済 (commit `1c14213`)

`viem_results/paper/run_lc_convergence.jl` に **`BLOCK_SIZE` 環境変数** を追加。

- 既定値 `BLOCK_SIZE=1` は従来動作 (single-orientation L=1) を完全に保つ → 既存 `convergence_*.hdf5` の再現性に影響なし
- `BLOCK_SIZE > 1` のとき: index 0 = `SINGLE_ORIENT (0,0,0)` 固定、index 1..L-1 を deterministic uniform-on-SO(3) filler で埋める (`MersenneTwister(RNG_SEED + 1)`)
- HDF5 への抽出は既存ロジック通り **column 0 のみ** → 出力 schema は完全互換

### 2.2 block-DDA_Py 側 — 編集なし

このメモ (`dda_results/paper/memo20260430.md`) のみ追加。`fig2_description.md` 等は L=32 計算が成功して図が再描画された後に追記更新する想定。

## 8. 課題・補足

- L=32 でも finest mesh が gate を通らない可能性は残る。production sweep (L=100) でも `solver_err ≈ 1.3-2.2×10⁻³` で gate を僅かに上回っていた事実があるため、本 convergence sweep (subspace 上限が production の半分以下) でも同程度か悪い可能性
- もし L=32 で通らなければ **L=64** (memory 倍増、約 16 GB → finest で 32 GB), あるいは **MAXITER=400** などの追加探索が必要
- 対策案を含む全体方針は `dda_results/paper/memo20260430.md` (このメモ) を保管 reference として更新していく
