## 1. 結論

**論文の LaTeX ソースは block-DDA_Py 内 `dda_results/paper/manuscript/` に
co-locate する** のを推奨する (paper repo を分離しない)。

理由:

1. `figures/*.pdf`、`fig*_description.md`、`memo*.md`、ipynb、HDF5 が
   全て同じ repo にあり、Claude / 共同編集者が文脈横断で参照できる
   (`「fig 3 §6.3 と paper §X が一致するか?」` 等のクロスチェック即時)。
2. `\includegraphics{../figures/fig*.pdf}` で直接参照 → 図のコピー不要、
   再生成時の同期コスト 0。
3. `fig*_description.md` は既に論文文体に近い散文で書かれており、Claude
   に LaTeX 化させる素材として直接使える。
4. 単一 git history で「コード変更 ↔ 図再生成 ↔ paper 文言更新」を一貫
   して追跡可能。今回の作業 (fig 1-4 全更新 + description 全更新) は
   co-locate でなければ整合性管理がほぼ不可能だった。

別 repo にすべきは: 共著者の repo 権限が異なる、Overleaf 同期前提
(部分的に可)、license 完全分離が要件、journal template repo を fork
等の特殊事情がある場合のみ。今回は該当しない。

## 9. 推奨ワークフロー (執筆フェーズ)

1. **執筆マシンで `git pull`** して最新の図・description を取得
2. `manuscript/` を新設、`paper.tex` skeleton を Claude にドラフトさせる
3. 各 section を `fig*_description.md` から発展させる形で執筆
4. 数値引用は HDF5 を直接読んで verify (Claude が自動できる)
5. 図の修正が必要になったら、執筆マシンで notebook 再実行 → figures
   再生成 (環境準備 = installation_guide.md と memo20260501.md §4)
6. `git commit` & push は section ごとに小さく (paper draft を別の
   branch `paper/draft-v1` 等で進めるのも可)
